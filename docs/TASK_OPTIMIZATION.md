## 0. 一句话结论

**克隆和情感能用，不是因为它们做得更精细，而是因为它们的 instruction 由前端按官方模板机械拼接，永远落在模型训练分布内；其余四个页面把用户手打的自然语言直接当 instruction 发给模型，而我们的管线里完全没有 PromptEnhancer 这一层，没有任何一步把口语翻译成标准句式，同时时长策略还用错了。**

关键结构性事实（已验证）：

- `backend/app.py:561` 把 `instruction` 原文塞进 ChatML text turn，`app.py:159` 只传 `gen_seconds`；`PromptEnhancer` / `prepare_generation` 只被 `src/auk/infer/infer_gradio.py:11` 导入，**我们的 Web 路径一行 PE 都没走**。
- PE 才是官方负责"任务分类、句式改写、锚点抽取、按任务算时长、VAD 裁剪、输入响度归一、输出限幅"的那一层（`pe.py:1163-1241`、`pe.py:1258-1284`、`pe.py:1953-2019`、`infer_gradio.py:264-280`）。跳过它 = 我们必须在自己的前端/后端里把这些职责补回来，否则就是在用"手打自由文本"要求模型给出"标准指令"的行为。
- 等长默认值有隐蔽副作用：`gen_seconds` 为 0 时 worker 转成 `None`，引擎按"输出=参考音频长度"生成（`infer_auk.py:316-320`）。对内容编辑这类"文本变长/变短"的任务，官方明确不用等长（见 §2）。

## 1. 逐功能诊断

### 1.1 指令 TTS（`#tts`）— 症状：声音单薄、描述稍微复杂就不听、长句容易断句奇怪

| 项 | 官方契约 | 我们的实现 | 判定 |
|---|---|---|---|
| 模板 | `请基于下面的描述: "{style_desc}",生成语音内容"{text}".`（`pe.config.yaml:412`，冒号/逗号/引号全半角，`:418-419`） | `frontend/index.html:60` 同一句式，逐字符一致 | ✅ 正确 |
| 无参考音频 | 空 latent + 文本尾追加 `\|<no_prompt_audio>\|`（`infer_auk.py:304-313`，训练同格式 `train.py:120-125`） | 引擎自动处理，我们没传 audio 即走这条路 | ✅ 正确（原先怀疑是坑，排除） |
| 语言一致性 | **text 语言决定模板与 style_desc 语言**：英文文本必须用 EN 模板和 EN 描述（`pe.config.yaml:419-420`，`pe.py:1028-1031`） | 无论中英**永远用中文模板** | ❌ Bug，英文朗读质量掉档 |
| style_desc 扩写 | PE 用 LLM 把短描述重写成多维描述（身份/场景/语气/音高/语速/句尾处理），示例见 `pe.config.yaml:421-423` | 用户输入 3–10 字直接塞进 slot（预设 chip 也就一句话） | ❌ 能力缺口：slot 信息量远低于训练分布 |
| 时长 | `tts_by_text`：F5 字节估算后 **再用 LLM 复核**，并卡 [0.4s, ratio 0.45–2.20]（`pe.config.yaml:108-118`，`pe.py:1193-1241`） | `estimateDuration()` 只做了 F5 那一半（`index.html:56`，字节率与 0.3× 短文本减速都对得上） | ⚠ 部分：无越界保护，超长文本会给出模型无法在等长内说完的目标（**需实测**是否就是"断句奇怪"的主因） |
| 反馈 | — | 无进度条、无输出时长、无采样率、结果卡只有播放器 | ❌ 用户无法判断"是我描述不好"还是"生成失败" |

**改法（按性价比排序）**

1. **[P0] 语言路由**：检测 `ttsText` 的 CJK 占比（>30% 走 zh 模板，否则 EN 模板），描述语言不一致时提示而不是静默混用。~10 行 JS，零风险。
2. **[P0] 时长上界保护**：`estimateDuration` 结果 >40s 时要求用户缩短文本（官方训练/参考实现的硬预算是 30s：`train.py:165-166` 0.3–30s、`nodes.py:21` `MAX_SEQUENCE_SECONDS=30`）。在 8GB 分页卡上，超预算的代价是分钟级耗时 + 显存溢出到内存（`infer_auk` 不报错，只会极慢）。
3. **[P1] 结构化声音描述构造器**（替代 LLM 扩写）：8 个维度单选/滑块（性别·年龄段·音区·语速·音量·情绪·场景·句尾处理），按官方 after 示例的句式拼成一条中文多维描述，例如
   `一位二十多岁的女性，在深夜独白场景中，用低语速、轻柔、略带气声的音色讲述。声音亲近自然，音量偏小，句尾轻轻下沉。`
   诚实定位：**这是 PE 扩写的近似版**，句式对齐训练分布但不会理解上下文；因此保留现有自由文本框作为"高级模式"（两者可叠加：结构化 → 填入文本框，用户可继续手改）。
4. **[P2，需批准] 本地 PE**：可选实验——用**已经加载**的 Qwen2.5-Omni Thinker 直接跑 PE 的 rewrite prompt（`pe.py:988-1032` 那份），同权重、不额外常驻显存，代价是每次生成多一轮 LLM 前向 + 需要给 `infer_auk.py` 开一个纯文本生成入口。**不进默认路径**（vendored 代码改动 + 结果不可控），只做成实验开关。

### 1.2 语音内容编辑（`#edit`）— 症状：改完话说不完 / 尾部被吞 / 改一个词整句重说

**这是四个功能里唯一存在确定性建模错误的页面。**

- **时长策略用错（proven）**：官方 `content_edit.duration.strategy = content_scaled`（`pe.config.yaml:187-188`），实现见 `pe.py:1263-1272 → _content_scaled_duration`（`pe.py:1782-1815`）。我们 `index.html:66` 走 `runGeneric(... , 0)` → 等长（`app.py:158`）。后果：把 5 个字改成 15 个字，输出仍然只有原句长度 → 说不完/吞字；反过来把长句改短则尾部塞进静音或幻觉音。
  前端注释 `index.html:62-63`「Editing tasks all use equal_length」**是错的**，应删。
  官方在无 ASR 时的退路正是我们能照抄的（`pe.py:1811-1814`）：
  `duration = base_duration × spoken(new) / spoken(orig)`，其中 `spoken = 0.21×CJK字数 + 0.30×英文词数`（`pe.py:1770-1779`）。
  `base_duration` 前端用 `Audio`/`decodeAudioData` 自己测即可，不需要后端或 ASR。
- **引号字符不匹配（suspicious，但零成本可修）**：官方中文模板用的是 **U+2018/U+2019**：`把‘{orig}’改成‘{new}’`、`删掉‘{target}’`、`在‘{anchor}’后面加上‘{text}’`（`pe.config.yaml:191-196`）；`pe.py` 内没有引号归一化逻辑（0 处替换），即 PE 是原样渲染配置模板的。我们的默认值和用户输入用 ASCII `'`（`index.html:16`）→ 与训练分布差一个标点。
- **只有一个自由文本框**：官方 6 个子类型（replace / insert_before / insert_after / delete / delete_before / delete_after，`pe.config.yaml:169-170`）都靠模型自己从一句话里理解；而且官方要求**一条指令只做一个意图**、重复词必须给 anchor（`:188` 附近说明）。我们让用户自由发挥 = 高频歧义。

**改法**

1. **[P0] 页面改成结构化表单**：模式下拉（6 子类型）+ 原句/锚点/新增文本三个字段 + 「一句话高级模式」折叠区（保留自由文本，满足既有偏好）。instruction 由前端按官方模板逐字拼装（含 ‘ ’ 引号），用户不再手写句式。
2. **[P0] 按子类型算时长**：replace → 上面的 scaling 公式；insert_* → `base × (spoken(asr≈anchor段) … )`，但我们没有 ASR，官方无 ASR 分支对 insert/delete **退化为等长**（`pe.py:1801` 的 `if asr_text:` 不成立，落到 `:1811` 的条件不满足 → `return base_duration`）。**照抄这个退化行为**并在 UI 注明"插入/删除整段时长度不变，替换会按字数自动缩放"。
3. **[P1] 输入音频时长显示 + 30s 提示**（同 §1.1-2）。
4. **[P1] A/B 对比试听**：结果卡并排"原音频 / 结果"，同步定位播放。内容编辑的验收标准是"只有目标词变了"，靠 A/B 才判得出来；现在只有单个播放器 + 下载。

### 1.3 语音 / 音乐分离（`#separate`）— 症状：能出声音但"分离不干净 / 说话人挑错 / 响度忽大忽小"

- **by_order 被写死成"第一个"**：官方是 `这段音频中只保留第{n_zh}个开始说话的人对应的语音，去掉其余说话人。`，n 无上限（`pe.config.yaml:358`，`pe.py:1635-1669`），而且 **COOKBOOK 的示例本身就用的第二个说话人**（`COOKBOOK.md:494-511`）。我们 `index.html:70` `sepInstruction()` 的 else 分支硬编码"第一个"→ 第二个及以后的人**根本选不出来**。
- **by_content 引号 + 尾巴不一致**：官方 `请只保留说‘{text}’的人，去掉其他说话人，输出等长纯净人声。`（`pe.config.yaml:357`；注：这里配置里是 `'`，与 content_edit 的 `‘’` 不同，**照抄各自模板原文即可**）我们的句子几乎一致（`index.html:70`）✅，这是四页里 instruction 最接近正确的一个。
- **cleanup_mode 完全没接**：官方 separation 支持与清理方式融合，`cleanup_mode ∈ {denoise, dereverb, denoise_dereverb}`，且明确"用户未显式要求时不要自行添加"（`pe.config.yaml:32-41, 349-352`）。我们没有任何入口 → 分离后带底噪/混响时无解。
- **缺官方输出限幅（proven）**：`extract_vocals` 是官方唯一做后处理的任务 —— 集成响度 > −14 LUFS 就拉下来，峰值 > 0.95 就限幅（`infer_gradio.py:173-175, 264-280`，依赖 `pyloudnorm`，失败则只限峰）。我们完全跳过 → 人声结果忽响忽轻、偶尔削耳。这就是"响度忽大忽小"的直接原因。
- **"去伴奏"没有官方模板**：官方 `extract_vocals` 只有 `singing_only` / `all_human_voices` 两个**保留人声**方向的模板（`pe.config.yaml:368-374`），**不存在 instrumental-only**，也没有多 stem。我们 UI 里"提取人声 · 去伴奏"的措辞把"保留人声"说成"去伴奏"，语义上等价于官方 `all_human_voices`，可以保留；但**不能承诺"输出伴奏轨"**。当前也没有多遍(multi-pass)方案。

**改法**

1. **[P0] 补官方输出限幅**：后端在 `sep` 的 vocal/singing 结果上执行 −14 LUFS / 0.95 peak（照 `infer_gradio.py:264-280` 逐行搬；`pyloudnorm` 不可用时退化为仅峰值限幅）。~20 行，收益最直接。
2. **[P1] by_order 支持任意 n**：说话人输入框加"第几个"数字框（留空=按说出内容挑选，二选一），模板用官方 `第{n}个` 句式。
3. **[P1] cleanup_mode 单选**（不选=不加，遵守 `:352` 的规则）：无 / 去噪 / 去混响 / 去噪+去混响，映射到官方变体池。
4. **[P1] 措辞与预期管理**：结果卡注明"AuK 是自然语言单目标分离，输出等长单声道，一次只保留一种声源；需要伴奏轨请分两次做（先取人声，再反向…）"—— 官方并无此工作流，标注为**限制**而非功能。

### 1.4 音频增强（`#enhance`）— 症状：噪声压不干净 / 人声发闷 / 音乐输入直接乱来

- **默认指令是正确的（proven）**：`enhanceInstruction` 默认值与官方 `enhance_speech` 中文模板逐字符相同（`pe.config.yaml:334` = `index.html:20`）。**原先怀疑"100 字段落对不上官方"这一条不成立**，报告里予以纠正。
- **但只有一个 flavor**：官方任务族有 denoise / dereverb / enhance(去噪+去混响) / restoration(电话感·闷声·削波·丢包)（`COOKBOOK.md:458-470`），以及 `improve_quality` 的 `bandwidth_extension` / `remove_effect`（6 类效果：telephone / megaphone / underwater / clipping / dropout / dc_offset，`pe.config.yaml:392-395, 1364-1534`），另有带"等长"承诺的训练派生句式（`pe.config.yaml:1196-1234`）。我们只暴露 `enhance_speech` 那一句 → **"只降噪不去了混响""去电话感""修削波"全都做不到**，用户改自由文本又回到 §0 的合法性问题。
- **无 VAD 是对的**：官方 `enhance_speech / separate_speech / extract_vocals / improve_quality` 都在 `vad.skip_tasks` 里（`pe.config.yaml:120`，理由：裁剪会把要保留的噪声/上下文切掉）。我们本来不做 VAD ✅ —— 但 `content_edit`/`emotion_edit` 官方**会**先 VAD 裁剪 + 0.1s padding（`:119-121`），这是 edit 页与官方行为的又一处差异（**需实测**影响大小；补 Silero-VAD 属于较重改动，见 §5 不建议项）。
- **音乐输入**：官方对增强/分离在音乐上的失效模式**没有任何文档**（全仓唯一的"别这么用"是歌词编辑必须 a-cappella，`COOKBOOK.md:187-190`）。所以我们只能自己实测出边界，再在 UI 里写限制。

**改法**

1. **[P0] 改成模式单选 + 官方句式库**（句子全部有 verbatim 出处，不要自己写）：
   | 单选项 | 官方 instruction（CN） | 出处 |
   |---|---|---|
   | 只降噪 | `请只去除背景噪声，保留其他内容，输出等长结果。` | `COOKBOOK.md:461` |
   | 只去混响 | `请只去除房间混响，保留其他内容，输出等长结果。` | `COOKBOOK.md:464` |
   | 降噪+去混响 | `请保留所有说话人，去除噪声和混响，输出等长的纯净语音。` | `COOKBOOK.md:467` |
   | 修复（电话感/闷声/削波/丢包） | `请修复这段音频的{X}，恢复自然清晰的人声。` | `COOKBOOK.md:470` |
   | 带宽扩展（高频被削） | `请对这段语音做超分辨率/带宽扩展处理，恢复被削掉的高频成分，输出宽带纯净人声。` | `pe.config.yaml:394` |
   | 去染色音色 | `请消除这段音频的{effect}音色，这段音频带有混响，请恢复成无混响的干声，输出自然清晰的人声。`（effect ∈ telephone/megaphone/underwater/clipping/dropout/dc_offset，`pe.config.yaml:1364-1534` 有 6 桶派生句式） | `pe.config.yaml:395` |
   前 3 项属 `enhance_speech`、后 3 项属 `improve_quality`（官方区分："脏"用 enhance_speech，"闷/糊/电话感"用 improve_quality，`pe.config.yaml:380`）。自由文本降级为"高级模式"。
   注：`COOKBOOK.md` 与 `pe.config.yaml` 的中文措辞偶有差异（如 `请保留所有人声，包括说话和歌唱…` vs `…说话和歌唱都算…`）；**以 `pe.config.yaml` 为准**，它是 PE 的实际渲染源，COOKBOOK 是文档变体。
2. **[P1] A/B 对比 + 输入时长/采样率显示**（同 §1.2-4，增强类任务没有 A/B 基本无法验收）。
3. **[P1] 结果信息回传**：输出时长、采样率、用时（见 §2 共性项）。发闷往往是"模型只按指令做了降噪、目标域不含宽带修复"，把这一点写成页面提示，比让用户反复重试更省时间。

## 2. 四个页面共有的三块短板（比单页改动更值得先做）

### 2.1 时长/信息反馈（P0，成本最低，体感改善最大）

现状：`app.py:570` 返回了 `sample_rate` **但前端从不用**；没有任何页面回传输出时长、用时、目标时长。只有克隆页有进度条，而且是**假进度**（8 → 18 → 100 三段硬编码，`index.html:59`）。四个通用页面只有按钮 busy + toast。

建议：

1. worker 返回值补 `out_frames`（`app.py:183` 一行），前端结果卡统一显示
   `结果 3.42 s · 目标 3.40 s · 24 kHz · AuK-Flash · 用时 12.4 s · seed 81234`
   长度对目标值的偏差就是这类任务最直接的质量信号（超目标→截断，欠目标→静音尾巴/幻觉）。
2. 上传时就测量并显示 `时长 / 采样率 / 声道 / 大小`，>30 s 直接红色提示（官方预算见 §1.1-2）。这是**唯一能在 8GB 卡上避免用户自杀式输入**的手段。
3. 计时器代替假进度（`elapsed` 每秒跳动）。真·step 进度需要在 vendored 采样循环里加回调（`src/auk/model/cfm_edit.py:143-216` 的 `fn` + 下游积分器），改动侵入上游代码 → 列 P2，需单独批准。

### 2.2 可复现性（P0，属于"能不能调好"的地基）

现在 **seed 从来不传**（`app.py:159` 只传 `messages/gen_seconds`）→ Base 每次结果都不同（引擎默认 `seed=None`，`infer_auk.py:299`），Flash 也因 `t_grid` 固定而相对稳定但仍含随机初值。用户"刚才那版更好"根本无法找回，任何参数调整都无法归因。

建议：前端默认随机 seed 并在结果卡显示 + 提供"同 seed 重跑"；后端把 seed 透传给 `engine.generate`。**这是四个页面共同的调优前提**，不做它，§1 里所有"改模板有没有效"都无法验证。

### 2.3 任务默认模型 / 参数建议（P1）

- 官方所有 recipe 都用 **Base**（`COOKBOOK.md:46-51`），Flash 是 4 步 DMD 蒸馏、CFG 硬锁 0（`infer_auk.py:325-329`）。分离/增强/内容编辑是**保真型**任务，蒸馏模型在这类任务上更容易出毛刺与细节丢失（**需实测**，但方向明确）。
- 我们全站默认 `flash`（`index.html:27`），且 `nfe/cfg` 完全不暴露 → Base 也永远是 32/2.0。
- 建议沿用你在显存策略上认可的做法：**显式开关 + 角标提示，不替用户自动决定**。在 edit/sep/enhance 三页顶部加一条 `模型建议` 提示（"这类保真任务建议 Base（更稳，慢约 N×）"，N 待 §4 实测填入）+ 一键切换；Base 下可选 质量三档（nfe 16/32/48），标注为实验参数。

## 4. 需要实测才能定论的项（等你点头再跑，会占 GPU）

报告里标了「需实测」的地方，建议用一次小规模基准收齐数据，而不是边改边猜：

- 矩阵：5 个任务（tts / clone / emotion / edit / sep）× {Flash, Base} × 输入长度 {5s, 15s, 30s} → 记录 `wall_time`、`nvidia-smi` 峰值显存、输出时长 vs 目标时长偏差、以及主观 1–3 分。
- 目的：填出 §2.3 的 "Base 慢 N×"、验证 §1.2 的时长缩放是否真的修好吞字、验证 §1.4 的"发闷"是否随模式变化、给 `estimateDuration` 的上界取一个有依据的值（PE 自己的边界是 ratio 0.45–2.20）。
- 成本估算：Flash 每次秒级~十几秒；Base 分页模式在 3060Ti 上单次可能分钟级 → 全矩阵约 30–60 分钟 GPU 时间，并会在 `outputs/` 落 ~90 个文件。
- 我不会自己开跑：**需要你确认现在可以用 GPU**（你那个 `启动AuK-Studio.bat` 实例上模型还挂着），或你自己按矩阵点几组我来读结果。

另外两项清理建议（与本次功能无关，顺手）：`outputs/` 已累积 43 个文件 / 22MB 且**永不回收**，`uploads/` 残留 4.8MB（`app.py:577-580` 只删成功路径的上传），历史记录只存 `{type,model,time,url}`、不存 instruction 与时长 → 无法复现。按你之前定的规矩（缺删/改接口就补功能、不手改数据文件），需要补一个 `DELETE /api/audio/{job_id}` + 记录字段扩充，放进 B4。

## 5. 明确不建议做（避免把报告变成许愿单）

1. **不引入 whisper / ASR**：`content_scaled` 无 ASR 分支已够用（`pe.py:1811-1814`），加 ASR 会多一个模型常驻显存 —— 8GB 上代价太大。
2. **不做多 stem 分离 / 伴奏轨输出**：官方无此模板与流程（`pe.config.yaml:359-374`），做了也没有可控预期。
3. **不把 PE 整体搬进 Web 路径**：它是 LLM-in-the-loop 的重管线（分类→槽位抽取→改写→时长复核），先做 §B2/B3 的"前端按官方模板拼 + 关键参数照抄公式"，性价比更高。
4. **不自动替用户选 Base/Flash**：沿用你认可的"开关 + 角标 + 危险档二次确认"，不做静默自动化。
